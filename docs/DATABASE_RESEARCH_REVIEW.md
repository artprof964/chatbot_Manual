This supports the heading-extraction warning without establishing a complete section hierarchy. Reviewed the HTMLParser code; did not rerun its entire character/table profile.
- Checked raw-vector illustration: 20,000 × 1,024 × 4 bytes / 1,048,576 = 78.125 MiB; report correctly excludes index and database overhead.
- Neo4j's official concurrent-access manual documents default read committed, nonrepeatable-read risks and explicit-locking behavior. The report does not claim snapshot MVCC for its baseline. The conventional clustering discussion distinguishes one write coordinator from one active client transaction and explicitly scopes out specialized sharding.
- Apache AGE's FAQ states PostgreSQL support through 16 while its current repository README lists 11–18. The report correctly exposes this documentation discrepancy and requires a released, tested version combination. pgvector's official filtering section confirms approximate-index postfiltering, possible short result sets and iterative-scan/partition alternatives.
- ArangoDB's current 3.12 feature page confirms Community binary restrictions from 3.12.5, the 100 GiB limit and separate BUSL source terms. Its transaction-limitations page confirms single-server/OneShard ACID scope and possible partial commits across DB-Servers during failure. The report avoids treating general distributed transactions as equivalent to OneShard.
- GraphDB 11.5 storage documentation explicitly states read committed, sequential update transactions and parallel readers, without a single-state transaction guarantee. Report claims are version scoped. Jena's TDB transaction documentation confirms TDB2 MVCC, serializable transactions, multiple readers and one active writer; its multi-JVM restriction supports access through a server.
- Neptune Database documentation confirms one primary, up to 15 read replicas, snapshot read-only queries and replica lag. Neptune Analytics vector documentation explicitly describes non-atomic/non-isolated embedding updates; the report keeps Analytics separate from Database.

## Judgment and limits

The recommendation fits the observed corpus and explicitly stated read-heavy/private-first assumption. It addresses shared clients, ingestion contention, deep/cyclic traversal budgets, provenance, duplicates versus contradictions, exact Unicode paths, independent version branches, and publication consistency. The five stack families have distinct selection conditions and disadvantages. The stress tiers, hardware envelope and latency objective are labeled proposals, not results. The compact-memory additions correctly preserve that provisional status.

No database was installed or benchmarked; no throughput, extraction accuracy, deployed PMS schema, licensing suitability for a particular commercial use, security configuration or recovery result was validated. Not every outbound link or peripheral feature was independently rechecked. Official current documentation can change; pin engine/extensions and review the applicable license before implementation. These limits do not prevent using the report to select the two proposed proof-of-concept candidates.
